# Changelog

Notable user-facing changes to API Key Case are recorded here. The package
remains pre-stable until 1.0; a listed version is not a promise of a future
release date or support period.

## [0.9.1] - 2026-09-14

Published to npm on 2026-09-14 (JST) from public tag `v0.9.1`, with
provenance through GitHub Trusted Publishing; `latest` resolves to this
version.

This pre-stable release adds the Agent-first Windows 11 + Hello workflow after
recorded real-host acceptance. macOS is a collaborative verification edition,
with native GUI and Accessibility acceptance tracked separately while
verification continues toward regular support.

- Changed the product-code license from MIT to the standard Elastic License
  2.0 (`Elastic-2.0`). Source, security-sensitive implementation, tests, and
  design records remain public. Only the managed instruction text generated by
  `agent-init` is separately available under standard 0BSD; the implementation
  remains ELv2. The MIT rights already granted for v0.9.0 are unchanged.

- Added closed history diagnostics and recovery guidance to CLI output and the
  Agent protocol. Missing history, locks, invalid data and storage failures are
  distinguished without raw errors or automatic cleanup. Start-save failure
  means this invocation made no provider write; result-save failure preserves
  its actual operation result. History reports are schema 2, existing stored
  journals stay schema 1, and readable metadata does not prove write access.

- Added Free `history --json` for new-chat resumption. Bounded local receipts
  distinguish past completed/incomplete/unknown operations, recorded key updates
  and destination changes; current remote values remain unverified. Failed start
  persistence blocks before provider writes; failed result persistence warns
  without retrying or changing an observed successful deploy into a failure.
  History never supplies approval, destination trust or automatic replay.

- Aligned current documentation, legal product facts and MCP handoff wording
  with Free readiness, Human Plane approval and host conditions. Marked older
  design/TTY approval examples as history and added the release acceptance
  checklist that this version passed before publication.

- The purchase link that `deploy` and MCP `deploy_secret` relay when Pro is
  missing now opens the site's purchase section, where the price, host
  conditions, Terms and refund policy sit next to the checkout button, instead
  of the bare checkout form. Pre-release legal review: the Terms now state that
  Free software use is governed by the bundled license and the privacy policy,
  that an Agent starting the CLI is not a person's consent, and that the
  liability limits apply only to the developer's slight negligence and never
  excuse the product's own defects as third-party causes; the privacy policy
  names each vendor's role and the analytics region; the landing page scopes
  the "not passed to AI" claim to the product's own paths.

- Updated the locked runtime dependencies `fast-uri`, `qs`, `hono`, and
  `smol-toml` to patched compatible versions and raised the corresponding
  override floors.
- Added Free deployment readiness to `next --json`, independently of the Pro
  license gate. The schema is now version 2 and includes host requirements,
  per-environment prerequisites/blockers, unverified conditions, and project
  registration counts/stages. Diagnostics never approve or deploy, and local
  registration is never reported as remote completion.
- Updated the exact-version Agent protocol so the user's own Coding Agent
  explains setup as one project task, coordinates existing dialogs and requested
  deployments, and stops on cancellation/failure. Added explicit
  `agent-init --host agents|claude|cursor` for fresh project persistence.
- Clarified in the exact-version Agent protocol that vault, history and provider
  login diagnostics belong to the current CLI account/home/session, which can
  differ from a human-owned shell when an Agent uses a sandbox. When Human Plane
  leaves a resumable process handle, the Agent now receives explicit guidance to
  wait or poll that same invocation instead of launching another call or asking
  for chat approval. No broker, resident service, privilege or approval bypass
  was added.
- Repaired the Windows approval/removal boundary exposed by same-session MSAA
  actuation. On Windows 11 build 22000+ **with Windows Hello set up for that
  account**, the plan button now starts HWND-bound OS user verification and only
  `Verified` approves; every other result, an account without Hello, and older
  Windows builds fail closed to a human handoff. That means Windows 10 and
  Hello-less accounts are handoff-only for high-risk deploy, `remove`, and
  `trust forget` — the CLI now names the requirement when it declines. Secret
  input and the Free/Pro boundary are unchanged.
- Added the Phase 6E lifecycle. `next --json` now reports project-scoped secrets
  the project no longer references as `status: "unused"` cleanup candidates, and
  returns `remove-secret` and `forget-deploy-destination` human actions so an
  agent can propose cleanup without knowing the CLI.
- **Changed `remove` to require the Agent-independent Human Plane, and removed
  its `--yes` flag.** Deleting a stored value is now decided in the same dialog
  used for high-risk deploys; there is no stdin confirmation and no fallback to
  the calling terminal, so an agent that owns this process's terminal cannot
  complete a deletion. Where that dialog is unavailable the command fails closed
  and points at the OS secret store's own UI. Scripts that relied on
  `remove --yes` must call the vault module directly instead.
- Added `trust status` and `trust forget` so a confirmed deploy destination can
  be inspected and, through the same Human Plane dialog, forgotten. Forgetting
  only ever causes the next deploy to ask for approval again; nothing creates or
  widens trust, and no destination fingerprint is printed.
- Changed Vercel `deploy` to request write-only storage itself: `production` and
  `preview` are now planned as `vercel env add <NAME> <env> --sensitive` instead
  of relying on Vercel's own default, which is a per-variable setting the
  environment does not imply. `development` is unchanged and never receives
  the flag, so a value placed there stays readable back, which is why it stays
  off the automatic-safe allowlist. Older Vercel releases rejected the flag in
  `development`; `vercel` 59.11.7 accepts it (measured 2026-09-08), so this is
  now this tool's own conservative default rather than a provider restriction.
- Added the Phase 6D Destination Boundary: every executing deploy is now bound
  to a Destination Identity, and a human confirming one records it in the OS
  secret store so the same destination does not ask again.
- Changed the deploy policy to deny by default. Only Vercel `preview`, in
  `project` scope, without `--force`, and on an unchanged confirmed destination
  can run without the Human Plane; `production`, GitHub, Vercel `development`,
  `--force`, `--scope user`, overwrite-capable steps, and first-use or changed
  destinations all keep the Phase 6C approval boundary. A side effect is that
  `deploy` now fails closed on macOS and Linux with the provider's manual steps,
  because the trusted CLI path is resolved from the Windows registry.
- Extended `next --json` with a closed per-target `deployment` block
  (`automatic`, `humanApproval`, `destinationTrust`) and an
  `approve-deploy-destination` human action. The schema still returns no
  command, argv, or Secret-derived value.
- Added the Phase 6B Human Plane Secret input path through `save --ask` on
  Windows. The fixed-path, sanitized helper writes directly to Credential
  Manager and returns status only; unsupported hosts fail closed without an
  Agent-owned terminal fallback.
- Updated `register-secret` Agent instructions and MCP `save_secret` handoff to
  request the Human Plane while keeping exact version pins and value-free MCP
  schemas. Production/GitHub approval and destination trust remain unchanged.
- Changed Phase 6A persistent Agent instructions to pin the exact version that
  ran `agent-init`, so a later pre-stable minor release cannot change an
  existing repository's Agent protocol without an explicit refresh.
- Added the Phase 6A Agent Control Plane: `agent-init`, safe managed project
  instructions with drift checks, and the closed status-only `next --json` schema.
- Documented the v2.1 destination/execution boundaries before the Phase C/D
  approval, trust-store, and deploy-policy behavior existed.

- Added privacy-limited PostHog usage telemetry for the explicitly documented
  LP events and for `scan`, `save`, `license activate`, and `deploy` results.
- Added the CLI's one-time pre-send notice, persistent opt-out controls,
  `DO_NOT_TRACK=1` and CI suppression, and a random anonymous installation ID.
- Aligned the website, Privacy Policy, security documentation, and package
  metadata with the v0.9.1 Free/Pro boundary.
- Hardened the reviewed public export, CodeQL checks, and npm release workflow.

- Included local scanning and redacted agent reports, OS-backed secret storage,
