Private operator/CI references and cross-product research are excluded. Earlier
published-release records remain available in this public repository's history.
This file does not declare a release, prove a real provider write, or authorize
publication. The candidate is separate from published api-key-case 0.9.2.

## Independent-review fixes — 2026-10-22

The source follow-up to the reviewed rc.1 corrects five reproduced defects:
Vercel's project ID table is read from stderr; relink preserves old v2 account
references without blocking an explicitly selected healthy v3; project-only
profile listing and identical plans expose an existing LaunchProfile ID;
ordinary registration retries find unfinished candidates before another input;
and the 60-second delivery approval limit is checked before start, separately
from the fixed command's 120-second completion timeout. Destination, generation,
configuration, presence, license and lock checks continue after execution.
Unknown operations still cannot be automatically replayed.

Windows/Node 24.15.0 automated checks passed: 92 targeted tests and one POSIX-only
skip, isolated Cloudflare 29 passed/one unavailable file-symlink-privilege skip,
hosted delivery 33 passed, local profiles/launch 20 passed, process recovery 17
passed, legacy credentials 19 passed, and local installed-package smoke. Package
smoke's first run failed a PID-marker assertion; clearing old mock markers before
the npx invocation fixes accounting for recycled Windows PIDs while still
requiring exactly one fresh mock load and the native-load guard.

An offline probe executed the unmodified inspect function and print method from
the [official Vercel 59.11.7 package](https://registry.npmjs.org/vercel/-/vercel-59.11.7.tgz)
with synthetic project/team metadata. Synthetic CLIs now emit the same stderr
table, ANSI ID and tab layout. Wrong, duplicate, stdout-only, oversized and
nonzero-exit results fail closed. A combined regression covers lost registration
response, unrelated legacy metadata, profile rediscovery and a completed delivery
observed after 61 seconds. No real Secret, provider write or new human OS
verification was performed. Earlier native acceptance below remains historical;
the original rc.1 pack and Public staging predate these fixes and are not claimed

verification. A subsequent GitHub attempt returned unknown and remained failed

## Protocol, compatibility and platform boundaries

The opt-in fixed-project `mcp --vnext` profile passed 16 tests together with the
legacy/guidance profiles. Two independent SDK stdio connections found the same
synthetic Binding and operation without re-entering a key. Tests covered fixed
physical project identity, Pro-first plans, invalid value/path/approval
arguments, redaction and observation without replay. This proves local protocol
behavior, not an actual ChatGPT/Codex host connection. No remote listener,
tunnel, credential transfer or global client-settings change was made.

Windows high-risk operations require Build 22000 or newer and OS Verified.
Unknown/older builds report those capabilities unavailable while retaining
the existing free input/storage boundary. New Ubuntu/macOS routes are not
accepted by these Windows results; legacy support remains separate.
